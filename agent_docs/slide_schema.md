# Deck schema

The authoritative definition is the Pydantic models in `backend/app/slides/schema.py`. If this file and that code disagree, the code wins; update this file.

## Shape (schema_version 1)

```json
{
  "schema_version": 1,
  "title": "Indonesia at a Glance",
  "theme": { "name": "blue", "background": "#01214A", "text": "#FFFFFF", "accent": "#F2B705", "font": "Calibri" },
  "slides": [
    { "id": "uuid", "layout": "title", "title": "Indonesia at a Glance", "subtitle": "Culture, nature and history", "notes": "" },
    { "id": "uuid", "layout": "title_bullets", "title": "A Tapestry of Cultures", "bullets": ["Over 300 ethnic groups", "..."], "notes": "" }
  ]
}
```

## Layouts in v1

| layout | fields |
|---|---|
| `title` | title, subtitle |
| `section` | title |
| `title_bullets` | title, bullets (1–8) |
| `two_column` | title, left (bullets), right (bullets) |

Every slide also has `id` and `notes` (speaker notes). Model layouts as a discriminated union on `layout`.

## Rules

- Slide `id`s are stable UUIDs, generated by the backend and never by the LLM. React keys, reordering and per-slide regeneration all depend on them.
- Text is plain text in v1, with no markdown or HTML.
- The schema enforces these limits: at most 30 slides, titles up to 120 characters, bullets up to 200 characters. The LLM's draft has to pass the same limits.
- Colors are `#RRGGBB`. The built-in themes carry over the prototype's three: `white` (#FFFFFF background, #000000 text), `blue` (#01214A, #FFFFFF) and `black` (#000000, #FFFFFF).
- The canvas is 16:9 (13.333 × 7.5 in). Sizes in the editor and in the PPTX use the same scale: title 36 pt, body 20 pt by default.
- The LLM returns a lighter `GeneratedDeck` (title, plus slides without ids or theme). The backend turns that into a full `Deck`.

## Versioning

- `schema_version` is an integer. Any breaking change bumps it and adds a step in `backend/app/slides/migrations.py` (`upgrade_deck(raw: dict) -> Deck` applies the steps in order).
- Stored decks are upgraded when they're loaded and re-saved in the new version the next time they're written.
- Frontend types come from the backend's OpenAPI schema (`npm run gen:api`). Don't hand-write duplicate TypeScript types.
